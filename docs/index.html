Quick Start

1. Include Puter SDK + sign in as GRUDACHAIN

<!-- Add to your HTML head -->
<script src="https://js.puter.com/v2/"></script>

// Sign in with the GRUDACHAIN Puter account
await puter.auth.signIn();
const user = await puter.auth.getUser();
// user.uuid is the userId to pass to grudaLegionAI

2. Import grudaLegionAI

import { grudaLegionAI } from './puter-ai-legion';

// Chat with persistent memory + rate limiting built-in
const result = await grudaLegionAI.chat("Design a leveling system", {
  core:   'grd17',        // which GRD-17 core to use
  userId: user.uuid,        // enables persistent memory
});

console.log(result.text, result.model, result.source);
// "Here is a leveling system..." | "claude-sonnet-4-5" | "puter"

3. Streaming with memory

for await (const chunk of grudaLegionAI.stream("Optimize this query", {
  core:   'grdsprint',
  userId: user.uuid,
})) {
  process.stdout.write(chunk);
}

4. Convenience core methods

grudaLegionAI.grd17("msg", { userId })   // System Core
grudaLegionAI.grd27("msg", { userId })   // Deep Logic
grudaLegionAI.dangrd("msg", { userId })  // Chaos Engine
grudaLegionAI.aleboss("msg", { userId }) // Boss Coordinator

Persistent AI Memory

Every user's conversation history with each Legion core is stored in Puter KV + FS. No cold starts — users pick up right where they left off.

Storage layout

// Puter KV (fast, rolling 30-day TTL)
"grudge_grd17_hist_{coreId}_{userId}"  → CoreMemory JSON

// Puter FS (persistent backup)
/GRUDA/grd17/memory/{coreId}/{userId}.json

Managing history

import { grd17Memory } from './puter-memory';

// Load a user's history with a core
const mem = await grd17Memory.loadMemory('grd17', userId);

// Get a summary for the UI
const summary = await grd17Memory.getSummary('grd17', userId);
// { messageCount, totalInteractions, firstSeen, lastSeen, profile }

// Clear history for a core
await grd17Memory.clearHistory('grd17', userId);

// Update user relationship profile
await grd17Memory.updateProfile('grd17', userId, {
  interactionStyle: 'technical',
  activeProjects: ['grudge-mmo', 'gruda-wars'],
});

Privacy: Secret keys and sensitive data are NEVER stored in Puter cloud. Only public keys, chat history, and preference profiles.

Best Practices

API call management

  • Pass userId to every grudaLegionAI.chat() call — enables memory AND rate limiting
  • Use rateLimiter.shouldPoll() before automation status checks (throttled to 30s intervals)
  • Prefer grudaLegionAI.stream() for long responses — avoids timeouts
  • Never poll /api/gruda-legion/grd17/automation/status faster than 30 seconds
  • Cache /api/gruda-legion/puter-ai/models on app init — models don't change often
  • Wrap all AI calls in try/catch — rate limit errors include retryAfterMs

Memory / storage

  • All Puter KV keys start with grudge_grd17_ — never deviate from this prefix
  • Store public keys in cloud; keep secret keys in localStorage only
  • Call grd17Memory.updateProfile() after learning user preferences
  • Maximum 20 messages per core per user in history (auto-trimmed)
  • Puter FS writes are async fire-and-forget — don't await them in hot paths

Core selection

  • Use grd17 for architecture, security, system design
  • Use grdsprint or ale for fast, low-latency responses
  • Use grd27 or aleofthought for complex multi-step reasoning
  • Use dangrd for creative, unconventional ideation
  • Use aleboss to coordinate multiple Legion calls in a workflow
